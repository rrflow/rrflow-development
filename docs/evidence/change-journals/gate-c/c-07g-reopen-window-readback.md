## Change and traceability

The old `lifecycle::reopen_inner` serial loop independently verified each pre-existing seed record and folded its effect in ordinal order into `c07g.reopened-corpus`. The replacement uses the existing `corpus::verify_window` through `verify_reopened_window`, with at most min(point clients, admitted queue, 64) requests. It retains the identical independent record, relation and vector oracle and rolling digest. A failed or cancelled window returns no partial window result; original per-operation and whole-lifecycle deadlines apply. Session rotation only occurs after the preceding window joined; lifecycle receipts and replay continue to be checked before the full corpus pass.

The driver checkpoints `reopened_corpus_verified` progress separately from initial corpus verification. The evaluation audit enforces point/seed membership, ordered bounded ordinals, and, when this new progress is present, matching count and digest against a completed reopen receipt. Older evidence without this added observation remains readable; no partial observation itself qualifies a lane. The generated progress-event schema is updated from the executable type. The exact prior code path, its behavior and the original `corpus_window` overlap/cancellation tests map to this replacement; no engine, workload size, frozen capacity/deadline limit or acceptance threshold changed.
