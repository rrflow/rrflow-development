## Brief and baseline

Starting local revision `38cefbb29983b8d5aca0cf9769b3c66999863351` contains the unmerged #292 dependency and the CI preflight package. The PR description was extended before implementation. The existing launcher buffers harness stdout until exit while `rrflow-eval` writes append-only `progress.jsonl`; the active 100,000-record ARM characterization is using an independent scratch observer and was not modified. The new opt-in observer reads that existing progress stream and selected owned Linux cgroup counters into a bounded, exclusive sibling sidecar. It does not control the campaign, copy event payloads or authorize a result. Windows reports cgroup counters unavailable. It is best-effort operator telemetry, not engine audit or qualification.

Read the launcher and `retain_launch` cleanup, Linux allocation and Windows job binding, `run_offline_lifecycle` execution, the existing launcher tests, `rrflow-eval/src/storage/progress.rs`, the installed sustained harness, C-07 owner and operations CI documentation. The change touches `scripts/ci/sustained_progress.py`, `scripts/ci/run_sustained_capacity.py`, `scripts/ci/test_sustained_launch.py`, `docs/operations/ci.md`, this record and generated navigation. No upstream code or product engine behavior was adapted. The observer begins after cgroup creation on Linux; on Windows it starts after image pinning and immediately before the job launcher, so it can report source unavailable before the native job is bound. A fresh sidecar is required. Normal stop joins before cgroup cleanup; if filesystem IO blocks beyond the bounded join, a warning is emitted and the daemon observer may finish later.
