## Baseline and change brief

Starting development main was `2e3a67d26295a763155a5129960d070914626704`, tree `bff177ef8ae17676ff9d8e7b8d7e1378e0fb88c1`. Opening commit `351eebabc9d111b1db741d81c433eab809b8a0c1` and the PR brief preceded implementation. This work ordinary-merges unmerged candidate PR153 `33d26f13f35b7406c8242a8550f048822f9890bc`, with its own PR152, PR142 and PR150 dependencies. The separate PR151 terminal record reports the 100000-record characterization failure at 48604 post-reopen readbacks with a pinned-byte admission label; it does not expose the denied numerical charge or establish that this defect caused that failure.

Previously every concurrent projected view charged the complete pinned manifest segment footprint even when the registry retained a single shared immutable generation. `Database::begin_projected_read` now separates that footprint from the captured memtable. `ActiveReadViews::acquire` charges each equal validated manifest generation once and each view's memtable separately. `ReadViewLease::release` subtracts its memtable and releases the segment charge only at the final generation reference. Different generations remain conservatively charged separately even where they share files. Existing active-view and pinned-byte ceilings, checked arithmetic, manifest identity checks, reclamation roots, per-view logical evidence, storage format and workload limits remain. No new runtime dependency or external code was introduced.

## First failure and verification

On Windows, `cargo test --offline --locked -p rrd-lsm --test projected_lifetime shared_generation_is_charged_once_until_its_last_view_releases` first failed with `ProjectedReadLimit { resource: PinnedBytes, limit: 1364, observed: 2728 }` for two overlapping views of one flushed 1364-byte generation. After the repair this focused test passed, reading the actual flushed value and checking final owner release. `cargo test --offline --locked -p rrd-lsm --test projected_lifetime` passed eight tests, including denial and non-leakage for additional memtable and distinct generation pins, conservative per-view memtable charging, old snapshot read, cancellation and drop. `cargo test --offline --locked -p rrd-lsm` passed the owning suite, including actual pinned-stream compaction/GC, adversarial lifetime, crash, and recovery tests; explicit ignored fixtures remain ignored. The suite began before the final extra per-view-memtable assertions were added; those assertions passed in the separately rerun focused target. `cargo clippy --offline --locked -p rrd-lsm --all-targets -- -D warnings` passed.
