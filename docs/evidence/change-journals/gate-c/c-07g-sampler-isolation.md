The draft change adds numeric-only phase timing to completed acquisitions at `sustained.rs::sample` and a bounded trace helper at `sustained/sample_trace.rs`. It reports native process/host collection, public diagnostics RPC, native memory walk and allocation-enforcement durations for samples taking at least 200 ms. It emits at most 64 observations and one exhaustion notice per process, without credentials, paths or external labels. It retains the prior resource observation timestamp, original checks and sample schema. It cannot observe time before acquisition, attribute a sample that never returns, or prove that sampling caused any rejection. Logging itself adds bounded instrumentation overhead. The installed mixed-family smoke now invokes the actual sampler against its owned native PID and asserts the returned PID, observation time and storage diagnostics before continuing its original restart/replay checks. The segment driver now uses `sustained/sample_task.rs` for one owned in-flight asynchronous acquisition while due load offers and completions proceed. It joins and records the result before leaving the offered-work section, denies overlapping samples and propagates errors and panics. Dropping the owner cancels an asynchronous pending task. The initial/final and non-offer paths still sample inline; synchronous native host and memory acquisition still runs on the current-thread runtime and can block offers. Therefore this is a partial scheduling repair, not proof that the native gap is repaired. The Windows real-executable smoke holds an owned async sample open while a real point read and independent verification complete, then executes the real sampler against the owned PID and retains the existing eight-record mixed-family restart/replay flow. It does not exercise `PointRun::segment` under injected sample delay.
