The installed document journey in #255 showed that a registered schemaless document is rejected as an unregistered record source. This package reproduced the defect on a real Windows rrflowKV store: `cargo test --offline --locked -p rrd-query --test query schemaless_document_projection_and_graph_join_survive_reopen -- --nocapture` failed with `Binding("record type note is not registered at this cursor")`. The first oracle creates a schemaless document table, two records with heterogeneous nested-map/string values and a typed graph relation, then reads through rrflowQL. No production code was changed before that red result.

The canonical query binder now recognizes a catalogue-declared schemaless record-like table. It admits untyped property names only in projection, after predicate binding, leaving dynamic property predicates and join keys rejected. The existing Arrow conversion chooses request-local physical representations from bounded read rows; its mixed-type representation is RRFlow's tagged canonical binary, not a native Arrow union or a persistent inferred schema. The tests check missing properties, empty results, mixed values, graph join on declared identity fields, update and old cursor, reopen, input-row denial, rejection of untyped predicates even when projected, and strict-schema rejection. Existing read stamps and read evidence remain authoritative. No runtime schema, data format, operation, project file, provider, external service or implementation path was deleted, moved or adapted.

Review then found that Arrow's internal `__rrd_identity` column can collide with a user property of that name. Before the guard, `cargo test --offline --locked -p rrd-query --lib reserved_identity_field_is_never_interpreted_as_a_document_property -- --nocapture` failed because the bridge accepted the collision. The PR brief was extended before this production change. Both record-batch and stamped-snapshot conversion now reject an internal identity name in either declared fields or supplied rows, including empty-result declarations. The focused Arrow test passed after the guard; the end-to-end test also checks explicit and wildcard query refusal. Record properties named like built-in fields such as `id` are currently overwritten in the query row; resolving arbitrary property namespace access requires a separately designed contract and is retained in POAM-005.

No Parquet pushdown, zero-copy execution or performance claim follows.
