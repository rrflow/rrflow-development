An actual Windows installed `rrflow.exe` from clean candidate source `fa945bc7142e0094100a5c28dd2d919edff63cf0` (binary SHA-256 `35f3791b09e620a6089fe88942a171d9a77d9c73e78b5a82a41e45d678be4e90`) reproduced this gap in a disposable existing Git project. Its `src/app.rs` contained `fn main() {}` and its `.gitignore` contained `/target/`; `git check-ignore -q -- target/build.bin` confirmed Git ignored the synthetic build output. After `rrflow install identity --json` and `rrflow install plan --project <project> --identity <identity> --mode existing --json`, the probe replaced only `target/build.bin` bytes `old` with `new`. Source bytes were unchanged. A second plan had a different `project_precondition_sha256` and plan SHA-256. `rrflow install apply --project <project> --mode existing --plan <original-plan> --expect <original-plan-sha256>` exited 1 with `error: ProjectBindingMismatch`.

The existing bounded `installation/inventory.rs` traverses project entries and excludes `.git`, `.rrflow` and the admitted installation lease, but does not generally exclude `target`, `node_modules`, or Git-ignored build output. The current default profile admits at most 100,000 entries and 1,073,741,824 bytes. Thus a routine build can invalidate a reviewed install preview; this observation does not prove a large project failed the bound. The source file and default profile were byte-identical between public main `2f232cb39dbac82e83371a5689f65ca501b72fb8` and tested candidate `fa945bc7142e0094100a5c28dd2d919edff63cf0`. Git is used by this diagnostic to establish ignore behavior, not introduced as an engine dependency.

Rejecting an actually changed bound precondition is intentional and remains required. The open design problem is to bind the relevant versioned source/effect scope, including explicit safe exclusions, without overlooking tracked sources, changed project-owned paths or the requirements for installation. The D-03 committed inventory must separately satisfy Git-correct rules, containment, races, bounded work, incremental change, interruption and restart. Do not simply ignore all Git-ignored data or bypass stale denial. This run does not prove D-03, the PR208 attunement start behavior for this fixture, project-file mutation safety, candidate CI, or alpha readiness.
