New source and tests are `engine/attunement/linux_supervisor.rs` and `linux_supervisor/tests.rs`; the existing engine module is changed to compile them on Linux only.

The Linux child is launched with a cleared environment, null standard streams, a pre-exec `RLIMIT_AS` and `PR_SET_PDEATHSIG(SIGKILL)`, plus a parent-PID check after registering the signal. Explicit termination and normal cleanup use the owned child handle. `RLIMIT_AS` bounds virtual address space, not resident memory or an aggregate process tree. The direct-child proof applies to the tested ordinary executable and supervisor process; privileged exec can clear the signal. Linux associates the parent-death setting with the creating thread. The initial implementation therefore killed a child when its requesting thread exited, even while the engine remained alive. The revised foundation keeps a dedicated launch thread alive for each owned child. This resolves the tested request-thread case; it is not yet a bounded worker scheduler. Before activation, design and test privileged-executable denial, executable identity and race handling, thread/concurrency admission, startup deadlines, process-tree cleanup, bounded reaping if the kernel does not promptly terminate a child, explicit pipes, deadline and durable publication. This foundation is not a filesystem/network sandbox and is intentionally unused by Parse.

Research: Rust's [`CommandExt::pre_exec`](https://doc.rust-lang.org/stable/std/os/unix/process/trait.CommandExt.html#tymethod.pre_exec) requires async-signal-safe post-fork work; Linux documents [`RLIMIT_AS`](https://man7.org/linux/man-pages/man2/getrlimit.2.html) and [`PR_SET_PDEATHSIG`](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html), including its parent-thread semantics and circumstances in which exec clears it. No upstream code was copied.

The first temporary WSL harness invocation failed because its manifest was inside the repository workspace without its own workspace declaration; the ignored harness was corrected without changing product inputs. The first source oracle then failed to compile with the absent Linux module. After implementation, the first test build failed to locate the nested test module under the temporary harness's absolute-path import; the explicit relative test-module path corrected that harness difference. The next parent-signal assertion failed with child exit 44: a separate C/pthread reproduction on WSL2 printed `main=9` and `thread=0`, establishing that querying the setting from the Rust test-harness thread was not an appropriate oracle. That assertion was replaced by a real supervisor-process-death test using a verified `/proc` parent identity and `pidfd` to observe the exact child.

The original focused suite exposed the creator-thread failure; the revised before/after oracle first failed with exit 137 when the child should have remained running, then passed after the dedicated thread was introduced.
