## Change brief and scope

Started from development main `81fce08e14497bbc280790beefe4666716355aec`, tree `0d92234da88dc5d4c0f14e15b01e6efa13a11f4f`, then integrated prerequisite [PR181](https://github.com/rrflow/rrflow-development/pull/181) at `b90532d9c0822040e2ef39fb9a64660d16295dfa`; bootstrap commit `9c910fd820a542cab6d1dc5ac82d9183d1eedb5f`. The draft PR brief preceded implementation and was amended before adding mandatory operation-reference metadata, the count fixture and language catalogue checks. PR181 must pass its candidate CI and land before this candidate; reconcile intervening main changes and regenerate projections. No release or roadmap status changed.

Previously the embedded engine could read a principal-scoped receipt but HTTP and clients had no operation for it. This change adds `attunement-receipt-read` under existing EstateRead authorization, keyed by job and original idempotency identity. The engine returns the previously validated immutable plan with its original status, principal and operation digest; the Rust client validates plan, status, digest shape, principal, instance and job identity. An absent or other-principal receipt is absent. Reads do not replay a command or verify present source. Ordinary authorization audit effects remain; HTTP invocation stores a body digest rather than the body. This is control-receipt readback, not a memory receipt, general execution plan, inventory, replan, live worker, or C-07 qualification. The broader open owner records remain unchanged.

Read owner records README, ADR-0002, one-engine execution plan, D-02a, POAM-040 and the full repository change-authoring procedure; inspected engine attunement and its receipt tests, contract attunement and operation catalogue/reference, HTTP dispatch and envelopes, client operation/session and installed HTTP fixture, generated-surface scripts, SDK generation and conformance runner, and synthetic fixture refresh generator. No external algorithm or third-party source was adapted. Existing control WAL, authorization audit and test fixtures provide trace and failure oracles; no throughput or resource claim is made. Generated projections are replaceable, not owners.
