Before considering production changes, inspected `engine/attunement/inventory/{records,publication}.rs`, `engine/{query,query_export,retrieval,data,context}.rs`, `rrd-store/src/repository/runtime.rs`, `access/versioned_read.rs`, `rrd-core/src/{runtime,authenticated_log}.rs`, `rrd-query/src/{pipeline,execute,index}.rs`, and `engine/model/lower.rs`. Inventory still publishes source entries under stable identities in intermediate transactions; the final head and checkpoint are committed together later. Normal query and hybrid paths use `StampedQueryPipeline`; direct data snapshot and context paths use `data_snapshot` rather than that single query entry point. Export delegates to scoped query. A query-only patch therefore would not establish consistent source visibility across these paths.

The runtime accumulator authenticates returned log entries against a captured `ReadStamp`. The existing store omission characterization demonstrates that an authenticated result from an incomplete event index does not prove the absence of a newer selection. The draft `SourceGenerationHistory` is an in-memory proof primitive with no production caller; its documentation explicitly requires an externally authenticated root and ordered writer. The root's relationship to each arbitrary requested runtime stamp and an engine-only selection-event authority remain design obligations. Public transaction lowering includes `AppendEvent`; the new selection kind cannot be trusted merely because an event is schema-valid. No new control authority, source fallback or consumer is implemented by this integration.

[RFC 9162](https://datatracker.ietf.org/doc/html/rfc9162) defines inclusion and append-only consistency proofs; [ICS-023](https://github.com/cosmos/ibc/blob/main/spec/core/ics-023-vector-commitments/README.md) describes neighbor-based non-membership under an ordered commitment. These are design references, not proof that RRFlow has authenticated range completeness or an endorsement of copying either runtime.
