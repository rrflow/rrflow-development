The existing worker protocol, source reader, publication and public contracts are unchanged.

The component configures an unnamed job with per-process and job-wide committed-memory limits and kill-on-close before creation. An extended startup job-list attribute assigns the child at creation; it is initially suspended, no handles are inherited, and the thread resumes only after successful setup. Owned native handles are closed through RAII. Explicit termination and drop have a bounded wait. This is not an OS filesystem/network sandbox, a resident-memory limit, an admitted executable identity, a pipe protocol, an end-to-end deadline or parser publication. It inherits the caller's environment; do not connect it to untrusted parser work until environment, executable identity, explicit handle/pipe admission and cancellation are resolved.

Primary research: Microsoft's [process creation](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw), [job-list attribute](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute), [job limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information) and [extended limit structure](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information) define the selected native operations. The job-list attribute is supported on Windows 10 / Server 2016 and later. The relevant memory limits govern committed memory; they are not RSS evidence. The planned pipe design must account for Microsoft's documentation that [anonymous pipe I/O is synchronous](https://learn.microsoft.com/en-us/windows/win32/ipc/anonymous-pipe-operations). No upstream source was copied.

They exercise the exact job association, queried job limits and real allocation denial, zero-limit refusal, explicit termination, drop cleanup, and killing the supervising process while observing the nested child terminate. The allocation fixture returns a distinct exit code after its assertions so a zero-test filter cannot pass; it checks the actual job limits before attempting the allocation. `cargo clippy --offline --locked -p rrd-engine --all-targets -- -D warnings` passed. The final `cargo test --offline --locked -p rrd-engine --lib` passed 335 tests with seven ignored subprocess/other fixtures, and `cargo test --offline --locked -p rrd-engine --test workspace_architecture` passed 33 tests. `cargo fmt --all --check`, `git diff --cached --check`, documentation-policy and navigation checks passed.
