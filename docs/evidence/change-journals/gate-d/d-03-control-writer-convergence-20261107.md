## Change brief and traceability

Starting draft `e3299b17ca21493dea378d992fdc0c317948cd2a` includes public main `d21a1556657fb17e783a4396368250459e03a2e8` and the failing [cross-consumer oracle](d-03-snapshot-consumer-20261107.md). The PR brief was amended before changing production. `rrd-store/src/repository/control.rs::commit_one_attempt` duplicated control CAS, journal hash chaining and watermark writes implemented by `prepare_control_batch`. The latter already owns multi-transition and runtime-plus-control commits. A source-generation design that added integrity state to only one path would leave real control commits outside it.

The canonical control boundary now shares `build_control_batch`, record and journal staging, and journal finalization between the single and composed writers. The catalogue path retains its original ordering: validation and encoding, catalogue revision calculation, record staging, index synchronization, journal staging and watermark, catalogue revision, authoritative commit. The batch path retains its per-entry record/journal staging order. No control record format, hash encoding, public operation, selection proof or runtime source visibility changed. Tested CAS and index-rejection outcomes remain atomic. Focused injected failures establish specific error precedence, not exhaustive failure precedence. Native I/O uncertainty remains. This is part of the incomplete D-03 candidate and does not fix the source leak.

Reviewed `repository/control.rs` lines 1–380, `rrd-store/src/control.rs` lines 1–190, `access/index.rs::synchronize_index_commit_bindings`, and the existing `control_journal`, `catalog_revision`, `native_index_commit`, and `installed_lifecycle` tests. Existing behavior includes CAS denial with no state change, a contiguous digest chain, concurrent writers, catalogue revision isolation, index-constraint rollback, and one physical runtime/control transaction. New tests compare exact single versus one-item batch journal/state after reopen and require the journal sequence and content to remain unchanged when native unique-index backfill fails. This is a specific boundary review, not an all-code review. No third-party implementation was adapted; the existing [transactional publication research](d-03-snapshot-consumer-20261107.md) explains why all related state must share one atomic commit.
