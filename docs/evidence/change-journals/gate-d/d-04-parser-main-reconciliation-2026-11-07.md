Platform research for the next parser boundary: Microsoft documents that `CreateProcess` with `bInheritHandles=TRUE` passes inheritable handles, while `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` limits the handles selected for that particular child ([CreateProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessa), [handle inheritance](https://learn.microsoft.com/en-us/windows/win32/sysinfo/handle-inheritance)). This supports the existing concern: a separate concurrently launched process that inherits all handles is not constrained by the parser child's handle list. The documentation also describes `DuplicateHandle` into another process, but does not establish a safe bootstrap protocol for this implementation. A new design needs an explicit, tested handle-transfer mechanism and process identity/termination guarantees; no fix or sandbox claim is inferred from these sources.
