## Change brief

At baseline, successful install replay worked only after `.rrflow/config.toml`
existed. An interruption before locator publication left a partial `.rrflow`
tree that retry rejected, after random token and operator-credential material
could already have been created. At the same time, product code still admitted
several competing creation or binding paths: `.rrflow/instance.toml`,
`InstanceManifest`, `ProjectAuthorityBinding`, raw-root engine openers,
`rrd-server initialize`, `rrd-security-bootstrap`, the `rrflow dev`
supervisor, raw primary-CLI commands, embedded MCP create/open, fixture-created
identities, local deployment preparation, and two Kubernetes initializers.

The bounded target was not a new installer. It was recovery and convergence
inside the existing `RrdEngine` authority:

- all no-write plan, project-inventory, target, profile, configuration, and
  executable checks complete before the first project effect;
- one owner-only, versioned, plan-addressed intent freezes the first accepted
  apply time, generated token bytes, generated operator-credential document,
  and their digests;
- retry accepts only the same plan, target, project precondition, profile,
  executable, and configuration, then creates or exactly verifies each
  directory, store, secret, semantic commit, pending locator, and active
  locator;
- storage is classified only as an exact empty owned store, exact committed
  install, exact published install, or complete replay. Partial or foreign
  control state, missing committed secrets, malformed/symbolic intent, and
  foreign/mismatched bytes fail closed without cleanup or guessing;
- acknowledgement removes only the exact owned intent and pending locator;
- outward product callers open installed state and cannot manufacture an
  instance; and
- the superseded successful source paths are deleted with replacement tests,
  not retained as migration, compatibility, or historical product lanes.

The product version remains `1.0.0`. Adaptive exploration remains governed by
ADR-0002 and no schema of thought was added. Arrow/DataFusion, native indexes,
reasoning execution, attunement phase execution, repair/restore/uninstall,
service management, external providers, Connectome implementation, platform
ACL qualification, signed bundles, performance thresholds, and promotion are
unchanged and outside this package.

The repository-local ignored `.rrflow/rrd`, `.rrflow/dev`, and
`.rrflow/verification` trees were never read, used as fixtures, migrated,
renamed, truncated, or deleted. Only the tracked four-line pre-canonical
`.rrflow/instance.toml` file was removed after replacement tests passed. A
user project containing pre-canonical or unknown `.rrflow` bytes still fails
closed and preserves those bytes.

## Trace, resource, debugging, and secret decisions

The engine emits bounded `rrflow::installation` stage observations carrying the
plan digest, non-secret installed instance identity, durable stage, recovery
classification, known replay disposition, planned managed-path/write-byte
counts, and elapsed time. The primary adapter separately emits
`rrflow::installed` plan/apply/serve/ready/verify outcomes, including apply
replay disposition and verification file/byte counts. Neither token/credential
bytes, project content, prompts, nor private model reasoning enter either
trace. Existing typed errors remain the failure oracle.

The debug oracle is a typed test-only observer, not an environment variable,
sleep, release hook, provider hook, or second lifecycle switch. It returns a
synthetic failure at each of eight stages: intent published, estate directories
ready, storage ready, token ready, credential ready, engine committed, locator
published, and intent acknowledged. The same production apply code executes on
retry.

Resource evidence is exact file inventory and hashes, not a throughput claim.
For every stage, tests assert one `RRD.TOKEN`, one operator credential, stable
token/credential SHA-256, frozen first-apply time, one installed semantic
outcome, no pending locator or intent after acknowledgement, mutation-free
exact replay, and byte-identical rejection fixtures. This package changes no
query/storage hot algorithm or benchmark threshold.

The current recovery intent serializes raw token and credential staging bytes
to an owner-only, 32-KiB-bounded, digest-bound file outside `.rrflow`, redacts
them from `Debug`, and removes that file only after exact acknowledgement. That
is deliberately documented as a local pre-release limitation: native Windows
ACLs, crash-residue secret accounting, memory zeroization, capability-scoped
external sinks, provider handoff, and rotation receipts remain open under
POAM-016/D-02/D-06/J. The journal does not claim the final secret contract from
this narrower result.

The current public apply method still accepts an injected `at_unix_ms`. The
primary CLI supplies its host wall clock and recovery freezes that first value,
but this package does not implement or qualify the target versioned
trusted-clock capability, rollback/skew policy, or clock-failure evidence. That
boundary remains POAM-006/-016 and D-02/D-06/J work.
