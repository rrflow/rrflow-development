# Installed typed document and graph journey

**Status:** active draft evidence; candidate and protected CI pending
**Coordinate:** `rrflow://rrflow-instance/data/evidence/change-journal/gate-h/h-04-document-graph-journey`
**Owner:** OBJ-02/07/09, H-04 and [PR #255](https://github.com/rrflow/rrflow-development/pull/255)

Starting public main `3a72a6b4adc43c842f67a59f4fc91d725eac7580`, tree `68edd7b9519fa363faca0220875e2a3bd2bac596`; draft bootstrap `97df2df0379fe5d49e9d9734a8615a5674d37cf2`. The PR brief preceded implementation and was updated before recording the newly discovered schemaless-query limitation. The existing installed example already wrote relational project/task records and a graph edge. This package extends its single engine transaction and public-client view with one typed nested document and a typed relationship to the task. The independent Python driver checks the expected values, endpoints, metadata, common cursor, scope, schema revision, and completeness. The Rust integration checks invalid and aborted transactions, historical readback and reopen. The fixture's fixed values are examples and test inputs, not runtime plans or product defaults. No implementation was moved or removed, no external backend introduced, and no roadmap gate was closed.

Research used [SurrealDB's record-link and graph-relation distinction](https://surrealdb.com/docs/learn/data-models/graph/record-links-vs-graph-relations) to distinguish a stored relationship with properties from a document field; no upstream source was copied. [PostgreSQL's transaction isolation documentation](https://www.postgresql.org/docs/18/transaction-iso.html) defines separate compatibility requirements; this journey does not establish them. Existing engine receipts and read stamps provide the relevant trace identity; sampled telemetry cannot substitute for them. This small synthetic fixture is not a resource, throughput, capacity or soak measurement.

The independent Python oracle was first extended against malformed document/edge cases; five negative cases failed before the driver was updated, and seven tests subsequently passed. The first real-engine test with a schemaless document failed at query binding: `record type devpulse_document is not registered at this cursor`. Inspection of `rrd-query/src/plan.rs::fields_for_source` showed the record branch checks `schema.records`; a schemaless record-like table has no strict record schema. The catalogue and transaction had accepted the document, but this query path could not bind it. The final example uses an explicit strict document schema, and [POAM-005](../../../poam/rrflow-1.0-alpha/poam-005.md) retains the schemaless-query deficiency; the typed example is not a repair for it.
