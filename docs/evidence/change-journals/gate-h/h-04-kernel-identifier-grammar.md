## Type decisions

| Type | What it holds | Decision and reason |
|---|---|---|
| `ProjectionId` | Public collection, vector, index and field ids, already `CanonicalId` at the public edge, and a few internal names | Canonical. Internal names change: `vector-edge-body`, `vector-exact-scan` |
| `RuntimeType` | Record, relation and event kinds. Every engine constant was already canonical | Canonical |
| `RuntimeId` | A record's id, or an event's identity | Canonical through `new`. An event identity only through `event`, read back through `parse` and `event_cursor` |
| `SnapshotId` | A SHA-256 from `SnapshotHandle::identity`, and one Raft snapshot name in `rrd-cluster` | Canonical. The Raft name becomes `raft-{sha256}`, so it holds the grammar and the length for any term and index. Its attributes carry each part |
| `RetentionPinId`, `OutboxId` | SHA-256 digests | Canonical, which they already were |
| `Subject`, `Predicate` | Claim coordinates. `model/lower.rs` is the only production writer, and it passes `CanonicalId` | Canonical |
| `Reader` | A principal in the access log, such as `agent:clyffy/worker`. No production code constructs one except the key decoder, and it never reaches the wire | Unchanged: it is not an identifier in a public record, and its form holds `:` and `/` |
| `ScopeId` | `instance:{id}`, `maintenance:{id}`, `project:*`, `cluster:*`, and text a public request supplies | Unchanged: the colon is its deliberate form, and the engine authorizes a scope against the session rather than projecting it through a canonical id |

<a id="event-identity"></a>

## Event identity

`cursor:{n}` stays, byte for byte. Renaming it to a canonical form would change every stored event identity and the digests over them, and it would let a client write a record of kind `observed` and id `cursor.7` that collides with the event of that kind at cursor 7. Today the colon reserves that namespace, because no public identifier can hold one, so `RuntimeId` now states that directly:

- `RuntimeId::new` takes the canonical grammar, so nothing a client supplies can name an event.
- `RuntimeId::event(cursor)` is the only way to issue the identity.
- `RuntimeId::event_cursor` reads it back, which replaces the text parsing in `raise.rs`.
- `RuntimeId::parse`, which storage, JSON and read-only queries use, accepts either form and only the exact text `event` writes, so `cursor:007` and `cursor:+7` are refused.
