## Current and target behavior

The public attunement endpoints had no typed Rust methods for start, step, pause, resume, expired-lease recovery, replan preview, accept or receipt read. The client now derives request/response operation marker types from every executable HTTP catalogue descriptor at Cargo build time, checks the compiled ID set against that catalogue, and binds the eight calls through those markers. The existing read, cancel and control-receipt methods now use the same generated dispatch while retaining their public signatures and response checks. The generator is repository-owned, uses the already-locked `rrd-contract` build dependency, writes only to `OUT_DIR`, rejects invalid, duplicated or unsorted descriptors, and has no install/runtime fetch or handwritten operation registry. `Empty` and the OpenAPI document are represented by unit and `serde_json::Value` respectively; other wire type names must compile as actual `rrd-contract` types. These generated markers are not evidence that all catalogue operations have complete public Rust methods or semantic conformance.

The shared contract now owns the replan seed, preview and acceptance digest calculation and validates preview/result/receipt lineage; engine receipt validation calls the same contract rules while preserving its stronger durable storage/generation checks. Control responses bind the requested job and next revision, and start/resume/pause/recovery check expected result states. The client verifies the supplied plan and expected instance before effects and validates response plan, identity, revision, principal and receipt digest afterward. Resume prevalidates only request shape and plan identity, allowing an identical idempotent replay after restart; the engine remains the authority for job state, revision, checkpoint, lease and authorization. Existing wire shapes and durable hash algorithm are unchanged. A frozen SHA-256 vector independently checks the old replan seed encoding. The old manually maintained 55-operation Rust reference table was removed because the candidate catalogue has 70 operations; live catalogue and generated coverage are the discovery sources.

Implementation traceability: replaced handwritten selection in `rrd-client/src/operation.rs` for read/cancel/receipt with `src/attunement.rs` and catalogue-generated markers; existing `rrflowdb_local` read/cancel/replay/reopen tests remain and pass. Replaced duplicated replan digest/receipt checks in `rrd-engine/src/engine/attunement.rs` with shared `rrd-contract/src/attunement.rs` validators; existing engine attunement and tampered-receipt/replay tests remain. Canonical owners are the executable contract and `RrdEngine`; H-04 and D-02 own acceptance. No legacy fallback, external adapter, product version or lifecycle authority was introduced. Changed paths are the two Rust crates' source/build/tests, the engine attunement source, installed lifecycle test and Rust reference; this journal and the generated Gate H index are evidence. The [earlier gap record](h-04-attunement-rust-client-gap.md) remains unchanged as historical evidence.
