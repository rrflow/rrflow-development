## Reproduced failure and repair decision

Before production edits, `cargo test -p rrd-store --test object_publication_race --locked` failed: ordinary process publication passed; simultaneous repair failed in a child with `ObjectMissing("1ae505acc3e990b9a6ea5a0f34a02a9e736c16e86828f00ad3397fb3b3e3e4c6")`. Both writers can observe corruption before either quarantines it; the second can then move a repaired winner or encounter the first repair's temporary absence. This is a real source-preservation finding, not a rename discrepancy.

Retain non-replacing, verified-winner publication for normal writes. Serialize only corruption recovery using crash-released filesystem locks, sharded by the existing digest prefix (at most 256 persistent lock files, created lazily). Recheck the object after acquiring the guard; a verified winner is adopted, never quarantined. Preserve the staged bytes on errors. Bound lock admission at 10 seconds and report timeout; no infinite waiting or digest/payload logging. Quarantine evidence names include process identity and use non-replacing publication so processes cannot overwrite one another's evidence. Public quarantine uses the same guard and rejects a now-healthy object. This expands the exact scope to the private repair guard and its process-death/bounded-admission tests in object/tests.rs; no new public storage API or second publication implementation. Required assertions cover healthy reader identity, corrupt evidence retention, same/different-digest publishers, lock release after process death, and clean staging after success. Joined verification remains the actual HTTP transaction/restart suite after the store suite passes.

The recovered diagnostic oracle is also adapted in tests/object_publication_trace.rs: repair admission emits wait-start/acquired/elapsed duration (and timeout on denial), never payload, digest, or root pathname. Healthy publication does not acquire or create a repair lock. This ports the useful observability assertion from PR219 without reviving mandatory locking for every write. The exact pre-edit declaration triage includes this original test; its current destination is now explicit.
