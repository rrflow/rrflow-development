## Problem, ownership and traceability

Starting public main `1f8fa02cf9df74ad5dab5b7481c49f68eeca96af`; opening commit `0d5c3c4e434d24e631edb6f14ffb793c8a8c54a0`. The PR brief preceded implementation. `git merge-tree --write-tree development/main development/codex/sdk-native-private-manifest` showed a single actual content conflict in `docs/roadmap/rrflow-1.0-file-plan.jsonl` for PR177. The existing generator rewrote that tracked whole-repository path/digest projection on each package; unrelated work therefore competed over generated content and could trigger full candidate re-integration and reruns. This record does not claim that every conflict or CI delay has that cause.

The canonical owner remains `scripts/ci/build_execution_inventory.py`: it enumerates tracked and non-ignored paths and parent gitlink identities, records bytes and hashes, maps current/planned paths to gates, and rejects incomplete coverage, unknown gates and unmerged index entries. Its current JSONL is now written to ignored `target/rrflow-1.0-file-plan.jsonl`; `--check` still recomputes and rejects missing or stale output. The old tracked JSONL path is a stable one-record retirement descriptor, not the current inventory. Its prior tracked Git blob was `445689a950d7d0f5146deaa88db887964e8ea709` at the starting revision; Git history retains its complete bytes. Historical journal links remain intact. The descriptor is validated by the documentation checker, and the updated navigation explains how to generate the current map.

The full candidate CI topology is preserved. In the existing verify job, CI requires a clean tracked and non-ignored checkout, generates the inventory, records `git rev-parse --verify HEAD`, checks that revision against `GITHUB_SHA`, verifies the generated output, and retains both files as a required CI artifact. Existing native and optional jobs, merge-queue requirements, tests, budgets and thresholds are not removed or deferred. The artifact is a discovery projection tied to the tested checkout, not a runtime build plan, approval, gate completion or truth by itself. The runtime handoff/source-identity work is unchanged.

Traceability: replaced the tracked generated projection, not the generator's Git inventory behavior; preserved existing gitlink, input-byte, unmerged-index, gate-assignment and missing/stale validation. Source and tests are `scripts/ci/build_execution_inventory.py` and `scripts/ci/test_execution_inventory.py`; CI policy and retention are in `scripts/ci/check_workflow.py`, `scripts/ci/check_documentation.py` and `.github/workflows/ci-reusable.yml`. Documentation owners are CI operations, implementation navigation, execution portal, roadmap index/current-alpha chapter and POAM-014; completed C-06g/j supporting-plan references clarify the old link without changing their evidence. This journal and its generated index are added. No engine source, persistent data, objective, roadmap/POA&M status or historical journal was deleted or rewritten.

## Observations and tests

- The first new inventory tests failed on the original generator: the ignored target path was still inserted as a phantom tracked self-record, the default output remained under `docs/roadmap`, and actual coverage included that phantom record. The first fixture attempt also failed because the temporary miniature repository did not assign every incomplete gate in the full roadmap; the test fixture was corrected to use a closed test roadmap while preserving the real gate IDs. This was a fixture setup error, not a product pass.
- The CI-artifact policy test first failed because its validator did not yet exist. After adding it, one mutation test initially removed an earlier unrelated `git rev-parse` rather than the inventory command; scoping mutation to the inventory step fixed the oracle. These failures were not hidden.
- `python scripts/ci/test_execution_inventory.py` passed 10 tests on Windows. They cover the original four gitlink/byte/index cases, current default output, missing/stale/forged-digest/tampered output, a new untracked input, independent Git paths and SHA-256, the historical descriptor, rejection of missing CI binding/retention checks, and two independent Git branches merging without changing the shared descriptor. Regeneration after either input change restores successful `--check`.
- An independent comparison against starting main's tracked JSONL compared 1,863 unchanged paths and found zero row differences; the descriptor deliberately changes from the old self-record to an ordinary current file. This comparison excludes changed paths and is not performance or product-qualification evidence.
- `python scripts/ci/test_candidate_admission.py` passed 11 tests; `python scripts/ci/check_workflow.py` passed with all three workflows, nine substantive jobs, five engine suites and six optional packages. The complete CI workflow diff contains only inventory clean-source checks, generation, SHA binding and artifact retention; all candidate and merge-group lanes are retained.
- `python scripts/ci/build_execution_inventory.py` and `--check` passed for the actual worktree; `git check-ignore` confirmed the output is ignored. `cargo test --offline --locked -p rrd-engine --test workspace_architecture --quiet` passed all 31 tests on Windows. Final documentation/navigation checks and clean-commit CI-step reproduction are recorded in the PR evidence after execution. A real hosted artifact upload, exact-head candidate CI and protected merge-group CI are not yet established.
