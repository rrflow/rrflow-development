## Canonical implementation and scope

`task-assessment-execute` and `task-assessment-read` have strict versioned
contracts. The descriptor declares one binary proposition, a finite score range
and direction, or distinct choice options. Answered results require correctly
typed values and nonempty unique references bound to exact source or practice
bytes. Abstention may have no references; any supplied references are validated.
Schema and byte-range validity do not establish semantic support or correctness.

The engine resolves one selected source from accepted inventory and computes
its source provenance. Practice text and template coordinates are explicitly
caller-declared; their exact UTF-8 digest is distinct from SWAG's structured-JSON
preview digest. No authenticated practice repository or automatic template
selection is implied. General assembled context is outside this first contract:
its unknown request field is rejected before reservation or provider dispatch.
The existing context-read permission and reviewed source/context-export consent
still protect source export.

The existing profile's configured controller supplies the endpoint. Assessment
policy is absent by default; false consent flags remain valid configuration and
deny execution. No selector attempt is required. The controlled task transaction
reserves one attempt and shared capacity, records the typed output internally,
and retains uncertainty without retry. Existing task-attempt v1 wire projection
remains unchanged; assessment output has a separate authorized read.

Relevant source, task, configuration and authority are checked at admission,
dispatch and completion. Equivalent selected inputs must survive unrelated
edits and inventory-head advancement. Historical output remains historical after
a content edit, but current revocation or source exclusion withholds it.
Arbitrary editors and remote dispatch are not an atomic transaction.
