## Brief and baseline

[PR163](https://github.com/rrflow/rrflow-development/pull/163) bound this scope before implementation and was amended before adding engine authentication and host-clock observation to its plan. Driver is this working session. Starting candidate is `89b3dae0d958df490ecc63e5e62db297c1142a5e`, tree `cfaea57450a5f3270ab8e5a01c7f3cb2eff7b280`: a branch from public development main `393e6b86ee58bb4ea4b77d14a871af339404ebb4` with the unmerged PR161 provider-source boundary ordinarily merged. PR161 remains a dependency; integration, candidate CI and merge are pending.

Previously no engine-owned configuration described incoming observation sources. `RrdEngine` now previews, reads, applies and revokes one revisioned source configuration in its existing installed-estate control storage. The contract binds sorted unique source IDs, producer IDs, designated collector principal, a closed OTLP-logs or ACP-stream declaration, metadata-only or content-authorized scope, finite source/event/batch limits, estate identity, expected current digest and revision. No source is activated and no event, content, credential or external endpoint is read by this configuration. A designated principal is a declaration: collector authentication and payload-scope enforcement do not exist until event admission is implemented.

Preview binds content and session to an exact digest, and the engine authenticates that digest using a domain-separated HMAC with the existing installed token key. This prevents a party without that key from changing plan content or time and simply recalculating its public hash. Apply requires an authenticated EstateAdmin session, verifies the authenticator and approved digest, checks installed identity, session, expiry and current revision/digest, then commits via the existing control CAS. Exact response replay is accepted only while the same publication remains current; later changes or revocation reject old replay. EstateRead permits read. The public methods use the existing engine host clock, not a caller-selected time; host clock trust remains explicitly unverified and rollback resistance is not established by this package. Internal engine clock-injection entry points support deterministic tests. Preview does not publish source configuration, but authorization retains its existing durable security audit: preview is not literally free of storage writes. Apply/revoke also emit the existing control-journal transitions.

Changed implementation paths: `crates/transport/rrd-contract/src/observation_source.rs` and its export in `lib.rs`; `crates/authority/rrd-engine/src/engine/observation_source.rs`, its `mod.rs` declaration, and `engine/tests/observation_source.rs` plus the `tests.rs` module declaration. No existing source is moved or deleted, no dependency or provider runtime is added, and no public transport operation or SDK is generated. This journal and generated navigation/inventory are the evidence paths.

## Checks and limits

On Windows with isolated `target/rroflow-source-binding-build`, four build jobs and test debug information disabled:

- `cargo test --offline --locked -p rrd-engine --lib observation_source`: two passed on actual installed estates. These cover no configuration publication on preview; digest tampering and rehashed forgery; foreign identity, other session, bad token, duplicate IDs, zero/oversized limits and unknown transport; independent active reader versus admin rights; issued-plan expiry at the injected clock; competing CAS; authenticated apply/revoke journal and public security-audit readback; normal close/reopen and stale replay. The second test bounds the public preview issuance time by the real host clock and exercises public apply/read.
- The installed lifecycle/concurrent-CAS test was run ten additional times with `cargo test --offline --locked -p rrd-engine --lib installed_source_binding_preview_apply_restart_revoke_and_replay --quiet`: ten passed. These are local thread races, not a cross-process interruption campaign.
- `cargo test --offline --locked -p rrd-contract --quiet`: all reported tests passed; no ignored tests were reported.
- `cargo test --offline --locked -p rrd-engine --lib --quiet`: 218 passed, three ignored.
- `cargo clippy --offline --locked -p rrd-contract -p rrd-engine --all-targets -- -D warnings` and `cargo fmt --all -- --check`: passed.
