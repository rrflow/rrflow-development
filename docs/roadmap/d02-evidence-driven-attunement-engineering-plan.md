## Owner direction

Recorded from the repository owner on 2026-11-10 and 2026-11-11:

- Eleven attunement steps declared in a profile file "will never work" for a reasoning engine. Attunement must be authored by the engine from real, research-grounded evidence about the project, dynamic rather than fixed, and tuned over time. The owner asked to be told if that direction is wrong. It is not; the qualifier is that a plan still has to be recorded, digested and replayable once it spends budget or persists state (OBJ-14).
- Folders and files must be grouped and context-aligned per [ADR-0003](../decisions/0003-configurable-estate-organisation.md): configurable domains with a tuned default, kind grouping, categories and tags, optional isolation, per-domain drill-down.
- "Any test is useless unless the database, the CLD, the LSM and the reasoning engine are actually working." Every package below is accepted by a real run of the installed engine on this repository, measured, and the first packages form one vertical slice that runs end to end before anything is optimised.
- SWAG runs on the GPU and LFG on the CPU. Only LFG is a core contention during prompt input.
- RRFlow is not SurrealDB; the owner needs the LSM store, the cold tier and the reasoning layer working as one engine that triggers the right plan and signal pool, slower at first, and competitive later.

## Design

**Capabilities with preconditions replace a sequence.** An attunement capability is a typed, versioned unit of work with a precondition over evidence, a declared effect, a budget shape and a verification predicate. The engine composes a plan as the ordered subset whose preconditions the current evidence satisfies, records the evidence digest it used, and executes only that. "Dynamic" means the selection is a pure function of evidence that changes when the project or its configuration changes; "governed" means the result is still a digested `AttunementPlan` with checkpoints and receipts. The vocabulary stays the current `AttunementPhase` names so no wire type is renamed; what goes is the mandatory sequence and the profile arrays. Comparable systems select work this way rather than running a fixed pipeline: SCIP indexers are "parallelizable, incremental, and language-agnostic" and re-index only changed files; Nx builds a project graph by static analysis of imports and configuration and enforces boundaries through tags; LlamaIndex's ingestion pipeline keys every transformation's cache on a hash of its input and configuration and skips unchanged documents.

**Evidence is the inventory plus classification.** Following GitHub Linguist's order, an entry is first classified as binary, vendored, generated, documentation or data before a language is guessed from modelines, shebangs, filenames and extensions. The project map's census becomes a projection of these records instead of a second walk. The classification is content-hashed with the entry so an unchanged file is never re-classified.

**Domains are proposed from evidence and applied only by an authorised revision.** ADR-0003's default is one shared `default` domain. The engine proposes domains from the folder table, workspace markers (Cargo workspace members, package manifests, Go modules, gitlinks) and dominant classification, and records the proposal; a project applies it through `PutSchema` as today. Architecture-recovery research finds that automated clustering "cannot recover module views in a sensible way" alone but is "a reasonable first step" for an expert-assisted process, which is exactly ADR-0003's rule that a proposal takes effect only through an authorised revision.

**Parsing is incremental by content hash and produces spans, symbols and AST chunks.** Only entries whose `content_sha256` changed since the selected generation are parsed. Symbol definitions and references come from tree-sitter tag queries per language; chunks follow cAST's greedy AST merge with a size limit (reported +4.3 Recall@5 on RepoEval and +2.67 Pass@1 on SWE-bench against line chunking). Spans keep byte offsets and the content digest of the exact source; ERROR and MISSING nodes remain evidence.

**Graph and ranking.** Definitions, references, imports and containment become temporal relations in the existing adjacency store. A repository map for context selection is a derived projection: PageRank over the reference graph, personalised toward the request's seeds, rendered within a token budget. That is Aider's design and ADR-0003's projection rule: derived, never canonical, never bypassing scope or grants.

**Lexical access persists and updates incrementally** by consuming the store's `IndexSourceDelta` (E-03), with a tokenizer decision recorded once (the dogfood harness showed underscore splitting decides answers).

**Embeddings are selected only when an authorised binding maps to a backend.** Feature hashing is never selected for a quality claim. SWAG is GPU work behind the same binding contract; LFG is CPU work and the only prompt-time core contention.

**Verification is engine-constructed.** Ground binds every produced record to its source generation and read stamp; Verify builds an `AttunementVerification` from per-capability predicates (counts, span readback after reopen, index cursor equals source cursor, per-domain coverage).

**Scope and evidence per domain** follow the H-11c to H-11e contract: `instance:{id}/domain:{d}` scopes that pre-filter rather than post-filter, a `Domain` resource kind for grants, and per-domain counts in diagnostics and retrieval evidence.

**Measurement is in the repository and the selector learns from it.** The dogfood corpus, questions and oracle move into `eval/lab` as a lexical, graph and mixed workload beside the vector tests; every run records the selection the engine made and the evidence it used, so a later package can tune selection from recorded results rather than opinion. Answer quality stays unmeasured until the owner approves a reader and judge model, as the lab already states.

**Correctness of the store is proved from outside.** Elle infers isolation anomalies from client-observed histories by cycle search and found anomalies in TiDB, YugaByte, FaunaDB and Dgraph; its caveat is that results are only as good as the recorded history. Deterministic simulation (FoundationDB, TigerBeetle's VOPR) requires the system to be built for it; Antithesis runs unmodified software in a deterministic hypervisor. The first oracle here is Elle-style over the public API with the existing kill fixtures, after the engine runs end to end.

## Research applied

- [SCIP](https://sourcegraph.com/blog/announcing-scip): incremental, parallel, language-agnostic indexing; re-index only changed files.
- [Nx project graph and module boundaries](https://nx.dev/blog/mastering-the-project-boundaries-in-nx), [monorepo tags](https://nx.dev/structure/monorepo-tags): boundaries inferred from static analysis and enforced through tags.
- [GitHub Linguist](https://github.com/github-linguist/linguist): classify vendored, generated, documentation and data before language detection; modelines, shebangs, filenames, extensions, heuristics, then a classifier.
- [cAST](https://arxiv.org/abs/2506.15655) (EMNLP 2025 Findings): AST-structured chunking with greedy merge and recursive split.
- Aider's repository map (tree-sitter tags, reference graph, personalised PageRank, token budget), as described in [RepoMapper](https://github.com/Cryect/RepoMapper) and related write-ups; verify against `repomap.py` before porting.
- Architecture recovery: [modularity clustering evaluation](https://eresearch.ozyegin.edu.tr/handle/10679/7008); [comparison of graph clustering for module views](https://scilit.com/publications/1237a16ac7068eddaf1f3588aa3e2c9c): automated clustering is a first step for expert review.
- [LlamaIndex ingestion pipeline](https://developers.llamaindex.ai/python/framework/module_guides/loading/ingestion_pipeline/): cache keyed by input and transformation hash; docstore upserts skip unchanged documents.
- [Bazel remote-execution digests](https://blog.engflow.com/2024/05/13/the-many-caches-of-bazel/) and content-addressed inputs: an action key over inputs, command and platform; incomplete dependency declaration yields wrong cache hits.
- [Elle](https://www.vldb.org/pvldb/volumes/14/paper/Elle%3A%20Inferring%20Isolation%20Anomalies%20from%20Experimental%20Observations) (VLDB 2020); [TigerBeetle VOPR](https://docs.tigerbeetle.com/about/vopr); [Antithesis on deterministic simulation](https://antithesis.com/docs/resources/deterministic_simulation_testing/).

These inform the design; none establishes RRFlow correctness or authorises copying upstream code.
