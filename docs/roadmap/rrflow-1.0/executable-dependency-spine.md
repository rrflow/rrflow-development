## Package readiness and evidence

An implementation package is ready only when its existing gate owner and PR
brief answer all of these questions with specific artifacts:

1. What user behavior changes, and what exact baseline fails it today?
2. Which existing operation admits it, with which identity, authorization,
   configuration and limits? If no such operation exists, name the contract
   decision and hold dependent implementation; do not overload an unrelated API.
3. Which source revision and input digests enter, which canonical records and
   derived outputs leave, and what transaction/checkpoint publishes them?
4. What does denial, partial work, stale lease, duplicate delivery, cancellation,
   disk/resource exhaustion and crash/restart do? Who resolves uncertain effects?
5. Which exact source/test paths are existing or planned, which prerequisite
   evidence is consumed, and what smallest failing oracle proves the change?
6. Which native command runs the joined proof; what fixture/model/corpus is
   pinned; which quality/resource thresholds are frozen before execution?
7. What bounded evidence proves the promised behavior, which work remains,
   and which condition stops the package for redesign?

The PR supplies executable commands when its code/test targets exist. A planned
test name is an implementation deliverable, never a command represented as
already runnable. Readiness does not require every later algorithm to be
selected, but each deferred choice must identify its owner, prerequisite,
alternatives, experiment and forbidden assumption. No ETA is justified merely
by file counts or an agent's confidence.

Use existing gate/J-04 capacity thresholds where applicable. For a new retrieval
or model quality profile, freeze the held-out corpus, scoring rubric, comparison
baseline and acceptance threshold in the owning package before measuring it.
Until that exists, report characterization, not qualification or superiority.
The current [admission gaps](../../poam/rrflow-1.0-alpha/poam-006.md#build-plan-admission-gaps)
prevent calling the whole next workflow implementation-ready. The owner's
subsequent implementation instruction authorized the bounded embedded package;
unresolved public admission still holds the work that depends on that decision.

owns implementation order; the technical requirements below do not impose a
second storage-first sequence. Prioritize the installed engine, real project

without displacing this local work. Existing qualification remains required.

requiring the entire project to fit in RAM or a model prompt. Queries select a
bounded, relevant working context from persisted indexes at a declared source
revision. Oversized inputs and incomplete indexes are visible states, not
silent omission. An installed binary, successful commit or small context demo
alone is not that alpha.

### Signals ship with every engine change

Every package declares its observable operation, units, scope, source and
configuration identities, cumulative-versus-window semantics, reset identity,
missing measurements and finite collection/export limits. Show admission/queue
wait separately from execution, and physical work separately from answer size.
At minimum retain ingestion/checkpoint progress, index source cursor and lag,
selected/skipped access paths, examined keys/pages/candidates/edges, cache hit
and miss deltas, retained memory, open segment handles, WAL sync/maintenance
cost, rejected/cancelled work and unresolved effects. Do not use project paths,
prompts or per-request IDs as unbounded metric labels.

Debug mode must be opt-in, bounded, redacted and usable through the engine's
public contracts without Connectome. A compact summary can link to detailed
samples/receipts; it cannot invent metrics or store a second truth. Capture
limits and dropped-sample counts remain visible. Measure debug-enabled overhead
against debug-disabled execution on the same workload. Existing A-07 vocabulary
and H-05 conformance own signal naming and cross-surface correlation.

### What a developer must see in Connectome

Open a folder, type a question, switch to another topic, correct a fact and return to the first topic after restarting RRFlow. At the original valid time, asking what the engine knew before the correction must yield the old answer. Asking with the later knowledge cursor must yield the corrected answer. Each answer must cite the contributing source revision, record or media span. The same question in a second isolated project must reveal none of the first project's evidence. An explicit sharing grant must identify which project, records and permissions it covers, and revoking it must exclude those records from subsequent retrieval.

1. **Open the project.** Workbenches and navigation are discoverable before a connection. On Windows the folder picker resolves slash and backslash spellings of the same directory to one project. Show whether this is an installation preview, an existing engram, a listening service, or an authenticated ready instance. Display the actual local endpoint, start/stop action and idle transition. A project can go idle without losing durable history. Connecting another instance or a hosted account requires an explicit choice about shared context. A process count, port or plan of managed files alone cannot establish readiness.
2. **Interpret the prompt.** Bind intent to an extensible schema and vocabulary revision. Preserve stable concept identities as aliases, definitions and relationships evolve. Show which global user policies and minimum requirements apply, which project requirements narrow them, and which preferences or nudges influenced retrieval. A behavioral inference stays an attributed proposal until admitted. A correction must retain its predecessor. Evaluate token savings against citation quality, correction handling and retrieval coverage at matched budgets.
3. **Execute within those constraints.** Semantic routing proposes eligible paths. A configured System One module may advise at an admitted decision point. Provider bindings translate binary or `noul`, score and choice into typed decisions and preserve the original response identity. `noul` denotes a binary-question contract. The engine enforces authorization and budgets. For every reported decision distinguish disabled, unconfigured, configured but unverified, available, refused, timed out and failed. Prove participation with the actual invocation receipt. SWAG, Jev, a Cloudflare endpoint or a custom controller must be replaceable behind this boundary. Claude, Codex, Grok and other provider integrations use the same public engine contract through the SDK, plugin or MCP adapter.
4. **Inspect the result.** The customer view shows the answer or abstention, citations, corrections and actionable failures. The internal build can open the same request and inspect its valid time, knowledge cursor, effective configuration, selected and skipped paths, keys and bytes touched, local latency, provider usage and durable writes. Keep unobserved values explicitly unknown. An operator can compare controller on/off or retrieval settings on the same inputs. Displaying a prior request must never dispatch another model call. RRFlow owns signals and routeable operations. Connectome projects them through existing domain routes.

The first client repair follows one existing call. In Connectome, `src/features/runtime/workbench/workbench.tsx` submits the prompt and reads the returned flight ID. In the engine, `engine/flight/launch.rs` runs context assembly for Pruned Observe and `engine/flight/records.rs` persists the stage decisions. Today Connectome's `src-tauri/src/rrd/client.rs` discards those decisions and ranked uses when projecting the detail. Carry the bounded typed evidence through the existing native view and render it in the shared Workbench/Flights result. Keep the original retrieval cursor and distinguish it from the later detail read. Its I/O counters measure the detail fetch. Charging them to the prompt would mislead the person tuning the engine.

Start with a retrieval packet containing a claim ranked before a document. The engine writes record-use edges using packet rank, skips claims, and subsequently requests edge IDs from one to the stored edge count. For a claim at rank one and a document at rank two, the writer selects edge two and the reader requests edge one. Characterize this at public flight readback before updating the view. Preserve the document's true packet rank and make the persisted edges discoverable after restart.

Use one project with a known matching document and one isolated project. Compare the rank, source identity, retrieval avenue, read cursor and stage reasons shown on the desktop with an independent authenticated read of the same flight, including after restarting the service. A Fresh flight should explain why it withheld context. A Pruned flight with no match should show the selection and empty result. Surface a failed read with its error. This repair covers flight evidence. Source ingestion, controller participation and answer generation each require their own receipts.
